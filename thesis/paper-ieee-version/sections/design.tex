\section{Design}
\label{sec:design}

Houdini is built using Python 3 and leverages a QEMU VM to provide a controlled testing environment for container security validation. Instead of running containers directly on the host system, Houdini starts a dedicated VM, ensuring that any security tests remain isolated and do not affect the host system. Within the Houdini configuration, one is able to specify the Docker version, kernel version, and runc version to be installed into the VM. The VM is created with the help of Buildroot, which enables the construction of minimal, reproducible Linux environments tailored for security testing. This high level of configurability enables our goal of easily testing how different kernel and container runtime versions affect policy enforcement. It also enables regression testing across versions to detect when security behavior changes unexpectedly.

At the core of Houdini’s architecture, a Flask-based server runs on the host operating system. This server acts as a bridge between the host and the VM, facilitating communication between them over a lightweight HTTP API. The Flask server is responsible for sending commands and configuration data to the VM and receiving trick execution results. When a trick is initiated, the Houdini client on the host instructs the VM to start a new trick. The VM then launches a container with the specified security configurations and executes the trick inside it.

When a trick is initiated, the Flask server exposes an endpoint that the Houdini client on the host uses to send a request containing the container configuration and the test logic to execute. The server then transmits this data into the guest VM. Inside the VM, a listener service receives this request, parses the configuration, and launches a container with the specified settings. The trick code is then executed within the container. Once execution is complete, the listener inside the VM collects the results, and sends them back to the Flask server. The Flask server then responds to the original request with the results, allowing the host to log the outcome.
