\chapter*{Abstract}
\fontsize{12pt}{14pt} \selectfont
\begin{doublespace}
Containers have become a foundational technology in cloud computing due to their speed, lightweight nature, and ease of deployment. However, ensuring that containers are truly secure and properly isolated remains a significant challenge. Most existing tools focus on scanning images for known vulnerabilities or validating configurations against security best practices. While these approaches are valuable, they do not confirm whether core confinement mechanisms, such as namespaces, cgroups, seccomp, or AppArmor are actually enforced during runtime. As a result, containers may appear secure on paper, yet still expose unexpected security gaps due to misconfigurations, version-specific behaviors, silent enforcement failures, or incomplete security policies.

To address this gap, this thesis presents Houdini, a modular framework for empirically testing container confinement. Houdini executes scripted tests, called tricks, inside an isolated virtual machine to observe whether security features like namespaces, cgroups, seccomp, and AppArmor are correctly enforced at runtime. By simulating real-world attack scenarios, Houdini reveals when isolation mechanisms silently fail.

Through a series of case studies, Houdini reveals misconfigurations, enforcement failures, and security inconsistencies in container behavior across different combinations of Docker, runc, and Linux kernel versions. These case studies demonstrate how seemingly secure containers can violate isolation guarantees due to subtle interactions between runtime settings and system versions. By making container confinement observable and testable, Houdini provides a practical, empirical foundation for building and validating more secure container systems.

\end{doublespace}
